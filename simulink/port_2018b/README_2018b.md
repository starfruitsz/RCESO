# b0 辨识移植到 MATLAB R2018b（无 C 编译器，走 MATLAB Function）

目标机只有 R2018b，且不支持 C 编译，因此**只走 `b0_ident_m.m` + `build_foc_m.m`**
这条路。C 版（`b0_ident.c` / `b0_foc2.slx`）仅作为参考基准，不要拷过去。

**分步操作见同目录的 `移植步骤_R2018b.md`：准备 → 自检 → 跑通算例 → 接进自己的模型 → 验证 → 排错。**

## 1. 为什么必须换实现

| 约束 | 后果 |
|---|---|
| C Caller 块 R2019b 才引入 | R2018b 没有，`b0_foc2.slx` 无法使用 |
| Simulink 不向下兼容 | R2023b 保存的 .slx 在 R2018b 打不开 |
| 目标机无 C 编译器 | 无法构建 MEX / 仿真目标 DLL |

MATLAB Function 块是纯 .m，正常仿真由解释执行，**不需要任何编译器**。

## 2. 要拷哪些文件（只有这 5 个）

| 文件 | 作用 |
|---|---|
| `b0_ident_m.m` | 算法本体（粘进 MATLAB Function 块） |
| `build_foc_m.m` | 一键建 `b0_foc_m.slx`（FOC + RCESO + MATLAB Function） |
| `run_foc_m.m` | 单独跑已建好的模型、输出闭环终值 |
| `test_b0_m.m` | **解析自洽测试，先跑这个** |
| `README_2018b.md` | 本文件 |

**不要拷**：`*.slx`（版本不兼容，必须就地重建）、`*.mexw64`、`*.slx.r*`、`slprj/`。

## 3. 目标机三步

```

2) build_foc_m        % 建模型并自动跑 130 s
3) type out_f2s.txt   % 看闭环终值
```

**第 1 步的预期输出**（R2023b 实测，R2018b 应完全一致，都是双精度）：

## 4. 时序（与 C 版一致，改动过）

| 项 | 值 |
|---|---|
| burst 周期 | **5 s，从 burst 起点计**（24 个 burst 恰好 120 s） |
| 单个 burst | 前 0.2 s 不注入、后 0.2 s 注入（各 200 拍） |
| 预热 | 前 3 个 burst 经 τ=kp/50 低通采纳，不直接跳变 |
| 冻结 | 第 24 个 burst 结束（约 115.4 s）取末 4 次均值，之后周期 3600 s |
| 时基 | 整数拍计数（uint32 → 在 .m 里就是 double 计数），**不用秒数累加** |

## 5. 端口（采样 1 ms）

| 端口 | 方向 | 单位 | 说明 |
|---|---|---|---|
| iq | in | pu | 实测 q 轴电流（A ÷ IBASE） |
| u | in | pu | 控制量，**须与 iq 同刻**（FOC 里取 u(k-1)） |
| **ge1** | in | 同 e1 | **G(e1)，块外计算后输入**：线性 ESO 直接接 e1，类 fal 接外部 G 块输出（两路反演都用它） |
| e1 | in | pu | 观测器误差 y − z1 |
| v | in | pu/s | 重复内模状态 |
| b0 | out | 标幺 | 初值 400，冻结后保持不变 |

> 反演用 `β1·SDFT(ge1) + (β2/Sd)·SDFT(ge1)`，G 不在块内推导。
> 原转速门限（omega_on/off）已移除，需要时在块外用使能信号实现。
| du | out | pu | 注入量，内部生成，需叠加到控制量上 |

## 6. 定标点（换电机只改这里）

| 参数 | 位置 | 说明 |
|---|---|---|
| 注入频率 | `f_inj = 65` | 须 5 Hz 整数倍，且 `f_inj*dT*nseg` 为整数 |
| 注入幅值 | `amp = 0.118` | 占比 ≤ 0.25 |
| 初值/限幅 | `b0_init=400`, `b0lo/b0hi=200/800` | 填控制器标称值 |
| 观测器带宽 | `wo = 500` | 必须与模型里的 ESO 一致 |
| 转速环增益 | `kp = 75.36` | 决定低通 τ=kp/50 |

## 7. 已知的坑（都踩过）

1. **MATLAB Function 块里不能有顶层 `error()` 断言**。放了会报
   “没有完全确定其输出 'b0out' 的维度”，整个模型无法 update/sim。频率-段长相干性检查
   因此只留注释与 `cyc_nseg` 变量。**这条正是本模型一度无法重建的原因。**
2. **别拷 .slx**：R2023b 存的模型在 R2018b 打不开，必须在目标机跑 `build_foc_m` 重建。
3. 若 `add_line(...,'autorouting','on')` 在老版本报参数不识别，把 `,'autorouting','on'` 去掉即可。
4. `Callee` 一侧的 `b0_res_t` 总线对象在这里**完全不需要**（那是 C 版的事）。
5. 目标机若勾选“加速/代码生成”模式才需要编译器；**正常仿真不需要**。

## 8. 与 C 版的等价性

在 R2023b 上把两版喂同一条 130 s 闭环记录流逐点回放（`cmp2.m`）：

| 项 | 结果 |
|---|---|
| 末值 | C 530.6365 / MATLAB 530.6365 |
| 全程最大相对差 | 9.2e-5 |
| 注入波形逐点差 | 3.2e-3 pu（256 点 LUT 相对 sin 的相位量化） |

## 9. 厂家 PMSM 模型（R2018b 版）

`pmsm_foc_2018b.slx`：用 **Simulink 自带 PMSM + 平均逆变器**重建的被控对象闭环，
已用 `Simulink.exportToVersion` 导出为 **R2018b** 格式。

### 9.1 里面有什么

| `ID` | 1 kHz b0 辨识（MATLAB Function） | `b0_ident_m.m` |

| `CC` | 20 kHz 电流环（PI + 反 Park） | `CC.m` |
| `PMSM` | SPS 自带永磁同步电机 | — |
| `CVS1-3` | 平均逆变器（三个受控电压源） | — |

### 9.2 打开后先改这几处

| 块/参数 | 默认 | 说明 |
|---|---|---|
| `PMSM` → Mechanical | `[1.89e-5 0 4 0]` | **必须显式设**：默认 J=0.0027 会让辨识测出 b0≈3.75（真实值/143） |
| `CC.m` 里的 `th = p*thm + pi/2` | — | Park 约定，静止注入标定得出，改电机会变 |
| `SL.m` 的 `kp` | 0.4 | 与 J=1.89e-5 配套；J 不同必须重调 |
| `TLf` 幅值 | 0 | 改成 0.1 就是 10 Hz 故障扰动 |
| `dB0` 初值 | 536.4 | 改成 800 即 +49% 严重失配 |
| `ID` 的 `upd_on` | 1 | 0 = 关闭辨识（对照用） |
| `ID` 的 `wave` | 0 | 0/1/2 = 正弦/方波/三角 |

### 9.3 两个注意

1. **不要在 R2023b 里打开后保存**——Simulink 会把它升级回 R2023b，R2018b 就打不开了。确认后直接关掉，别点保存。
2. 导出时 Simulink 报了三条例外警告（CC/ID/SL 的“将数组当作一维矩阵”）。这是 R2021b 才收紧的行为；
   在 R2018b 上仍按旧语义运行，与本模型的写法一致。若以后要迁到 R2021b+，
   需把 `blast(1:nfrz-1) = blast(2:nfrz)` 这类线性索引改成显式循环。

### 9.4 目标机（R2018b + ERT）编译注意事项

**① 冻结循环不能用动态上界切片**

原写法 `b0v = mean(blast(1:max(nblast,1)))` 在 ERT 下报：

> Variable-size arrays are currently disabled for code generation ... line 155: blast(1:max(nblast,1))

已改为定长数组 + 动态循环上界（`for i = 1:nf, bs = bs + blast(i); end`），
代码生成器可接受，且数值结果不变（本机验证 b̂0 = 545.1，与改前一致）。

**② 端口数据类型**

ID 块的输入若是 single 而模型里是 double，会报：

> Input 'u' expects a signal of data type 'single'. However, it is driven by a signal of data type 'double'.

在该块的 5 个输入（iq / u / ge1 / e1 / v）前各加一个 **Data Type Conversion**（输出 `single`），
或在块端口属性里把数据类型设为 `Inherit via internal rule`。

**③ powergui 的库链接**

导出后 `powergui` 的库链接是 inactive（Simulink 导出时的已知现象）。
在 R2018b 打开后若提示，右键 → Library Link → **Restore**，或直接删掉重放一个 powergui
（参数：Discrete，Ts = 1e-5）。

### 9.5 运行使能与稳态判据（2026-11-25 更新）

接口扩为 7 个输入：

```
function [b0out, duout] = b0_ident_m(iq, u, ge1, e1, v, w, wref)
```

| 参数 | 默认 | 含义 |
|---|---|---|
| `upd_on` | 1 | **0 = 完全不辨识、同时取消注入**（du 恒 0、b0 停在 b0_init） |
| `w_gate` | 0 | 启动判据：|w| < w_gate·|wref| 不启动（0=关） |
| `w_ss` | 0.02 | 稳态判据：|w − w_lp| < w_ss·|wref|（0=关） |
| `w_hold` | 0.1 | 稳态判据需**连续保持**的秒数 |
| `tau_w` | 0.2 | w 的一阶低通时间常数 [s] |

w 与 wref **单位必须一致**（建议都用 rad/s）。

### 9.5.1 为什么要连续保持

故障扰动（如 10 Hz）每半个周期都会穿过低通值，瞬时判据会在过零点短暂满足——
实测只用瞬时判据时，10 Hz 故障下 burst 仍会启动（b0 从 536.4 爬到 543.2）。
加 `w_hold = 0.1 s` 的连续保持后，故障下完全不再启动。

### 9.5.2 实测（本机 130 s）

| 工况 | 转速 | b^0 | du 峰值 |
|---|---|---|---|
| 基线（识别开） | 599.8 rpm | **545.1**（+1.63%） | 0.0500 |
| upd_on = 0 | 600.0 rpm | 536.4（不变） | **0.0000** |
| 10 Hz 故障 0.1 N·m | 636.2 rpm | 536.4（不启动） | **0.0000** |

### 9.7 fi / non-fi 比较报错的修复（2026-11-25）

目标机报：

> In fi < non-fi, or non-fi < fi, the non-fi must be a constant.
> line 84: "abs(w - wlp) < w_ss*abs(wref)"
> line 95: "abs(w) >= w_gate*abs(wref)"

原因：模型里 w/wref 是**定点（fi）**，而 `w_ss*abs(wref)` 是 double，
R2018b 不允许定点与非定点直接比较（除非非定点是常量）。

修复两处：

1. 入口统一转 double：

```matlab
wd  = double(w);
wrd = double(wref);
```

2. 判据改成**归一化比值与常量比**，不再出现变量对变量：

```matlab
r_ss = abs(wd - wlp)/max(abs(wrd), 1e-6);   % 归一化稳态偏差
if (w_ss > 0) && (r_ss < w_ss)             % 与常量 w_ss 比
r_w = abs(wd)/max(abs(wrd), 1e-6);         % 归一化转速
ok_w = (w_gate <= 0) || (r_w >= w_gate);   % 与常量 w_gate 比
```

本机复验（输入本就是 double）：599.8 rpm、b̂₀ = 545.1、du 峰值 0.05 —— 行为不变。

**目标机需要重新执行一次** `update_b0_block.m` 覆盖代码。

### 9.8 “稳态不注入”的排查与修复（2026-11-25）

**现象**：闭环进入稳态后完全看不到注入。

**根因**：稳态判据原来是 `|w-w_lp| / |wref| < w_ss`，分母用 wref。
若 w 与 wref **单位不一致**（例如 w 用 rad/s、wref 用 rpm 600），
比值会被放大，永远大于 2% ⇒ 判据永不成立 ⇒ 一次都不注入。

**修复**：分母改成自身的 |w|，判据与单位无关：

```matlab
r_ss = abs(wd - wlp) / max(abs(wd), 1e-6);   % 相对转速脉动
if (w_ss > 0) && (r_ss < w_ss)               % 与常量 w_ss 比
```

本机验证（130 s）：

| 场景 | b̂₀ | du 峰值 |
|---|---|---|
| 稳态，wref=62.832 rad/s | 545.1 | 0.0500 |
| 稳态，wref 故意=600（单位不一致） | 545.1 | 0.0500 |
| 10 Hz 故障 | 536.4 | 0.0000 |

**排查清单**（稳态不注入时按顺序看）：

1. `upd_on` 是否为 1 —— 新语义下 0 = 不辨识**也不注入**；
2. `w` 是否接到实测转速 —— 若恒为 0，r_ss 判为“不稳态”，永不注入；
3. `t_start`（默认 8 s）未到之前不注入；
4. 是否已经 `frozen` —— 24 个 burst（120 s）跑完后按设计停止注入；
5. 临时把 `w_ss` 和 `w_gate` 都设 0，若注入恢复 ⇒ 就是门限判据的问题。

### 9.9 稳态不注入：五分钟定位法（2026-11-25）

按顺序做，每步只看「注入有没有出现」：

**第 0 步：临时关掉所有门限，强制立刻注入**

```matlab
t_start = 0;    % 立刻开始（不用等 8 s 稳态）
w_ss    = 0;    % 关闭稳态判据
w_gate  = 0;    % 关闭启动判据
upd_on  = 1;    % 必须是 1（0 = 完全不辨识也不注入）
```

- **有注入** → 是门限判据的问题（回到 9.8 逐项调 w_ss / w_gate）
- **仍无注入** → 往下走第 1、2 步

**第 1 步：确认块是按 1 ms 执行**

双击块，看 MATLAB Function 的 **Sample time**（不是模型的 solver 步长）。必须是 `1e-3`。
若继承成 1e-5（常见），则：

- `nxtick = 8000` 实际只等 0.08 s；
- 每段 200 拍 = **2 ms**，注入变成 2 ms 的小尖峰，示波器上看起来就是没有注入。

设置方法（脚本）：

```matlab
rt = sfroot;
ch = rt.find('-isa','Stateflow.EMChart','Path','你的/块/路径');
ch.ChartUpdate = 'DISCRETE'; ch.SampleTime = '1e-3';
```

**第 2 步：确认 w 接到了实测转速**

若 w 恒为 0，则 r_ss = 1（判为不稳态）→ 永不注入。用 Display 块或示波器看一眼 w 是否有非零值。

**第 3 步：确认没有提前冻结**

24 个 burst（120 s）跑完后 frozen = 1，按设计停止注入。

### 9.10 目标机参数对照（2026-11-25 实拍）

实拍到的块参数：

```
amp    = 0.05;     wave   = 0;      b0_init= 200;
b0lo   = 20;       b0hi   = 2000;   wo     = 300;   kp = 30;
upd_on = 1;        t_start= 5.0;    w_gate = 0.3;  w_ss = 0.1;
```

**问题 1：w_gate = 0.3 卡住启动**

启动判据要求 `|w| >= 0.3*|wref|`。若 w 与 wref **单位不一致**
（w=62.8 rad/s、wref=600 rpm），比值只有 0.105 < 0.3 ⇒ 永不启动 ⇒ 稳态也不注入。
这解释了为什么改 `w_ss` 无效（稳态判据在启动判据之后）。

处理：**先把 `w_gate` 设 0**；要保留门限就把 w 与 wref 统一成同一单位。

**问题 2：b0_init = 200 配首窗守卫**

首窗守卫要求首个估计落在 `b0_init ±50%` 内（即 100~300）。
若系统真实 b0 不在该区间，所有窗都会被丢弃，b0 永远停在 200。

处理：新增开关 `first_win_guard`（默认 1）。对 b0 标称没把握时设 0 先放行，
看到量级后再填 b0_init、把守卫打开。

## 推荐的目标机起始参数

```
upd_on  = 1;
t_start = 5.0;
w_gate  = 0;        % 先关，确认能注入后再按同单位开
w_ss    = 0;        % 先关
first_win_guard = 0;% 先关，看到 b0 量级后填 b0_init 再打开
```

确认注入正常后，再逐项打开判据。

| 3 | active | burst 期间为 1（每 burst 400 拍） |
| 4 | tick | 以 1000/s 增长；不增长 ⇒ 采样率不对 |
| 5 | nxtick | 首值 8000，之后每 5000 递增 |
| 6 | wcnt | 稳态时涨到 ≥100 |
| 7 | r_ss | 稳态应 < w_ss |
| 8 | w | 实测转速；恒 0 ⇒ w 没接 |
| 9 | du/amp | 注入段为 ±1 |
| 10 | \|E1\| | e1 的 65 Hz 分量幅值；**恒 0 ⇒ e1 没接/为 0** |
| 11 | \|num\| | 差分分子 \|Δd̂ + b0·Δu\| |
| 12 | \|den\| | 差分分母 \|Δĩ\|，应 ≈ amp |
| 13 | bq | 本窗估计；为 0 ⇒ 该窗被守卫丢弃 |

### 9.11 删除首窗守卫（2026-11-25）

**原因**：首窗守卫要求首个估计落在 `b0_init ±50%` 内。
严重失配时（例如 `b0_init=250`、真值 536，偏差 114%），
正确的估计会被当成异常丢掉 ⇒ b0 永远停在初值，辨识永久失效。
这与「严重失配下仍要拉回」的目标直接冲突。

**现状**：只保留两道与标称值无关的保护：

1. 相对判据：|Δĩ| > 0.25·amp（电流必须真的跟上注入）；
2. 硬限幅：[b0lo, b0hi]。

**复测**（130 s，J=1.89e-5）：

| 工况 | b0 初值 | b̂0 终值 | 误差 vs 真值 536.4 |
|---|---|---|---|
| 基线 | 536.4 | 545.1 | +1.63% |
| 严重失配 | **250（−53%）** | **545.9** | **+1.77%** |

即：初值偏离一倍以上，辨识仍能在 120 s 内拉回到 +2% 以内。
